# План: Термінальний чат TUI з нуля

Цей файл описує архітектуру та кроки реалізації. Коду тут немає — писати його треба самостійно.

---

## 1. Ідея

Будуємо мінімальний термінальний інтерфейс (TUI) для чату з ШІ. Термінал працює в RAW mode. Екран поділений на зони. Потік символів від "ШІ" йде у верхню зону. Користувач друкує у нижньому рядку.

```
┌──────────────────────────────────────┐
│ You: привіт                          │
│                                      │
│ AI: abcdefgh...                      │  <- зона історії + поточний AI-потік
│                                      │
│                                      │
│                                      │
├──────────────────────────────────────┤
│ > мій текст тут|                     │  <- рядок вводу, курсор в кінці
└──────────────────────────────────────┘
```

## 3. Типи даних (state.go)

### Message
Структура для завершених повідомлень.
- `sender string` — хто написав: `"user"` або `"ai"`
- `text string` — текст повідомлення

### AppState
Головна структура стану додатка. Містить ВСЕ, що треба для рендерингу одного кадру.
- `width int` — ширина терміналу (у символах)
- `height int` — висота терміналу (у рядках)
- `history []Message` — завершені повідомлення (і user, і ai)
- `input string` — текст, який зараз друкує користувач
- `aiOutput string` — текст, який зараз "друкує" ШІ (потік з SudoText)

**Чому `aiOutput` окремо від `history`?**
Потік ШІ йде символ за символом. Ми не знаємо, де кінець речення. Тому накопичуємо його окремо, а коли вирішуємо "фіналізувати" — додаємо як `Message` у `history` і скидаємо `aiOutput`.

## 4. RAW mode (main.go)

### Вхід у RAW
Використовуй `term.MakeRaw(int(os.Stdin.Fd()))`. Функція повертає `*term.State` (попередні налаштування).

### Вихід з RAW
**Обов'язково** відновлюй термінал при будь-якому виході. Використовуй `defer term.Restore(...)`.

**Порядок `defer` важливий** — вони виконуються LIFO (останній зареєстрований — перший виконується).

Рекомендований порядок відновлення:
1. Показати курсор (`\x1b[?25h`)
2. Відновити термінал (`term.Restore`)

### Alternate Screen Buffer
Коди `\x1b[?1049h` (увійти) та `\x1b[?1049l` (вийти).
Це створює "чистий аркуш", як у vim. Після виходу твій shell залишається чистим.

**Рекомендація:** використовуй alternate screen.

### Курсор
- `\x1b[?25l` — сховати курсор
- `\x1b[?25h` — показати курсор

Сховай курсор перед рендерингом, покажи після (або перед виходом).

## 5. Event Loop (main.go)

Головна горутина (`main`) — це event loop. Вона НЕ читає клавіатуру напряму. Вона читає канали.

### Канали
- `keyChan chan string` (або `chan []byte`) — події клавіатури
- `aiChan chan string` — символи/слова від ШІ

### Цикл
```
for {
    select {
    case key := <-keyChan:
        // обробити натискання
        // оновити state
        // викликати render(state)
    case text := <-aiChan:
        // додати до state.aiOutput
        // перевірити, чи час фіналізувати
        // викликати render(state)
    }
}
```

### Graceful shutdown
Коли користувач натискає `Ctrl+C` (або іншу клавішу виходу):
1. Горутина клавіатури пише сигнал (або закриває `done`)
2. AI-горутина бачить `done` і виходить, закриваючи `aiChan`
3. Event loop виходить з `for ... range aiChan` (якщо range) або перевіряє закриття
4. `main` завершується, спрацьовують `defer`
5. Термінал відновлюється

**Важливо:** `main` має "пережити" AI-горутину. Якщо `main` зробить `return` раніше — `defer` спрацює, але AI-горутина може спробувати писати в канал після закриття.

## 6. Клавіатура (keyboard.go)

### Чому `os.Stdin.Read`, а не `fmt.Scan`
У RAW mode ОС не буферизує ввід. Кожен байт приходить одразу. `fmt.Scan` чекає пробіл/Enter — не підходить.

### Читання
Читай у буфер розміром 1-3 байти:
- 1 байт для звичайних клавіш (`q`, `a`, `1`, `Enter`, `Backspace`, `Ctrl+C`)
- 3 байти для Escape-послідовностей (стрілки, наприклад `\x1b[A`)

### Таблиця клавіш
| Клавіша | Байт(и) | Дія |
|---------|---------|-----|
| Друковані (a-z, etc.) | ASCII код | Додати до `state.input` |
| Enter | `13` (`\r`) | Відправити `input` як user-повідомлення, очистити `input` |
| Backspace | `127` | Стерти останній символ `input` |
| Ctrl+C | `3` | Graceful shutdown |
| Esc | `27` | Можна використати як cancel або ignore |
| Стрілка вгору | `27 91 65` (`\x1b[A`) | Поки що ignore |
| Стрілка вниз | `27 91 66` (`\x1b[B`) | Поки що ignore |

### Горутина
Функція `keyboardListener` запускається як `go keyboardListener(...)`. Вона читає `os.Stdin` у циклі і пише у `keyChan`.

**При помилці читання** (наприклад, термінал закрито) — горутина має завершитися, а не крутитися вічно.

## 7. AI-потік (ai.go)

### Потік
Використовуй `RepeatFunc` з `done chan struct{}`. Горутина читає `done` і виходить, коли канал закритий.

### Фіналізація повідомлення (затичка)
Оскільки SudoText видає безкінечний потік символів, треба вирішувати, коли "речення ШІ закінчилося".

**Варіант-затичка:** коли `len(aiOutput) >= N` (наприклад, 50 символів), фіналізувати:
1. `history = append(history, Message{sender: "ai", text: aiOutput})`
2. `aiOutput = ""`

Це імітує "ШІ відповів" і починає нове повідомлення.

### Важливо
Функція `handleAI` (або логіка в event loop) має перевіряти цей ліміт і скидати `aiOutput`.

## 8. Layout (layout.go)

### Розмір терміналу
`term.GetSize(int(os.Stdin.Fd()))` повертає `(width, height, error)`.

### Розподіл рядків
- Останній рядок (`height-1`): рядок вводу
- Передостанній рядок (`height-2`): роздільник
- Рядки `0` до `height-3`: зона історії

### Word wrap
Текст повідомлення може бути довшим за `width`. Треба розбити на рядки так, щоб кожен рядок вміщався.

**Алгоритм:**
- Маєш рядок тексту і максимальну ширину
- Йдеш по словах (або символах)
- Накопичуєш у поточний рядок
- Якщо додавання наступного слова перевищує ширину — починаєш новий рядок
- **Префікс:** рядки з `sender` мають префікс `"You: "` або `"AI: "` (перший рядок), наступні рядки того ж повідомлення мають відступ (пробіли)

### Функція `buildLines(state) []string`
Перетворює весь стан у плоский список рядків, готових для виводу.

**Вхід:** `AppState`
**Вихід:** `[]string`, де кожен рядок — це те, що має бути надруковано на екрані (вже з перенесенням)

**Що включає:**
1. Рядки з `history` (кожен `Message` через word wrap)
2. Рядок з поточного `aiOutput` (префікс `"AI: "`)
3. Рядок роздільника (`──...`)
4. Рядок вводу (`"> " + input`)

**Прокрутка:** якщо загальна кількість рядків більша за `height-2` (зона історії), показуємо ТІЛЬКИ останні рядки, що вміщаються. Це створює ефект "скролу вниз".

## 9. Рендеринг (render.go)

### Чому НЕ `\x1b[2J` кожен кадр
`\x1b[2J` очищає ВЕСЬ екран. На швидких оновленнях це може миготіти (flicker). Професійні TUI перемальовують "інтелектуально".

### Правильний алгоритм рендерингу

Кроки (у функції `render(state)`):

1. `\x1b[?25l` — сховати курсор (щоб не стрибав під час малювання)

2. `\x1b[H` — курсор у верхній лівий кут (рядок 1, колонка 1)

3. Отримати список рядків через `buildLines(state)`

4. Для кожного рядка:
   - Надрукувати текст рядка
   - `\x1b[K` — очистити рядок від курсора до кінця (стирає "залишки" попереднього кадру)
   - Якщо це не останній рядок — `\r\n` (перенести курсор на новий рядок)

5. `\x1b[J` — очистити все, що нижче поточного рядка (на випадок, якщо попередній кадр був довший)

6. `\x1b[row;colH` — поставити курсор у потрібне місце (рядок вводу, після `"> " + input`)

7. `\x1b[?25h` — показати курсор

### ANSI шпаргалка
| Код | Дія |
|-----|-----|
| `\x1b[2J` | Очистити весь екран |
| `\x1b[H` або `\x1b[1;1H` | Курсор у верхній лівий кут |
| `\x1b[K` | Очистити рядок від курсора до кінця |
| `\x1b[J` | Очистити екран від курсора до кінця |
| `\x1b[row;colH` | Абсолютне позиціонування (1-based) |
| `\x1b[?25l` | Сховати курсор |
| `\x1b[?25h` | Показати курсор |
| `\x1b[?1049h` | Увійти в alternate screen |
| `\x1b[?1049l` | Вийти з alternate screen |

## 10. Кольори та зони (після бази)

### Сірий фон для AI-повідомлень
ANSI background color: `\x1b[48;5;240m` (сірий з 256-кольорової палітри) + `\x1b[0m` для скидання.

### Як реалізувати "коробку"
Кожен рядок у зоні історії можна перевіряти: чи належить він до AI-повідомлення. Якщо так — додавати перед рядком ANSI-код фону і `\x1b[0m` в кінці.

**Важливо:** колір змінює ширину? Ні, ANSI-коди не займають місця на екрані, але вони збільшують довжину рядка у байтах. `term.GetSize` повертає ширину у символах, тому при word wrap треба рахувати тільки видимі символи, а не байти ANSI.

### Рекомендація
Реалізуй спочатку чорно-білу версію. Коли рендер працює ідеально — додай кольори як окремий шар.

## 12. Поширені помилки

### "Термінал залишився RAW"
Якщо програма впала (panic) і `defer` не спрацював — термінал залишиться без echo.
**Ліки:** у shell виконати `reset` або `stty sane`.

### "Ctrl+C не працює"
У RAW mode `Ctrl+C` не генерує SIGINT. Це просто байт `3`. Твій код має сам обробити його.

### "Стрілки не працюють"
Стрілки — це 3 байти (`\x1b[A` і т.д.). Якщо читаєш по 1 байту, треба накопичувати їх у буфер і розпізнавати послідовність.

### "Миготіння екрану"
Якщо використовуєш `\x1b[2J` кожен кадр — на великих оновленнях буде видно миготіння. Перейди на рендеринг з позиціонуванням.

### "Довгі рядки ламають layout"
Термінал сам переносить рядки, якщо ти надрукував більше символів, ніж ширина. Це зламає твій підрахунок рядків. Word wrap має бути на твоєму боці.

## 13. Як дебажити

1. **Запускай з `script` або перенаправляй stderr у файл:** `go run . 2>debug.log`. У коді можеш писати `log.Println(...)` у файл, не засмічуючи термінал.

2. **Використовуй `fmt.Fprintf(os.Stderr, ...)`** для логів. Stderr не йде через термінальний buffer твого TUI.

3. **Запускай без RAW mode** для тестування логіки: зроби умовний флаг або закоментуй `MakeRaw` і тестуй `buildLines` звичайним `fmt.Println`.

4. **Якщо термінал "застряг"** — натисни `Ctrl+J`, потім набери `reset` і `Enter`. Або відкрий новий термінал.
