Plums Roadmap

Only the work needed to make Plums reliable enough for broader use.

Before Beta

  • Replace the temporary agent registry in internal/core/registry.go with real agent discovery, metadata, and validation.
  • Define provider behavior for sessions, messages, models, tools, questions, and errors.
  • Decide whether codex is stable or experimental, then document and test that choice.
  • Harden config loading for config.toml, layout.json, and commands.json.
  • Add clear startup errors for missing binaries, invalid config, port conflicts, and unsupported terminals.
  • Add a small /help view with keybindings, slash commands, config paths, backend, model, and session.
  • Document install, first run, config, keybindings, providers, skills, and troubleshooting.

Before 1.0

  • Add plums doctor or plums --doctor for non-interactive setup checks.
  • Make stream cancellation explicit in the UI and keybindings.
  • Verify keyboard, paste, mouse, resize, and modified Enter behavior in common terminals and tmux.
  • Expand tests for provider startup, health checks, sessions, message streaming, tools, questions, slash commands, and palette actions.
  • Make releases repeatable with version metadata, release notes, and an install path.
  • Review every public README and config claim against actual behavior.

Later

  • Themes and more layout presets.
  • Search chat history.
  • Export transcripts.
  • Rename or delete sessions when providers support it.
  • Copy last assistant message or code block.
  • Shell completions and package manager distribution.
  • Provider plugin loading.
  • Token, cost, and attachment support when providers expose them.
