Step 2 — Dead code removal

Remove genuinely unreachable code while preserving reserved seams and the public extension API (which is “unreachable” only because external user configs call it).

1. Plan for this step

  1. Run golang.org/x/tools/cmd/deadcode ./... from the real entrypoint.
  2. For every flag, grep the whole tree including tests (deadcode ignores test-only callers) to classify: truly dead vs. test-used vs. public API vs. reserved.
  3. Remove only the truly-dead set. Re-run go build, go vet, go test ./..., gofmt -l.
  4. Re-run deadcode to confirm the set shrank to only intentionally-retained items.

4. Explicitly NOT touched (reserved seams)

Per DESIGN.md §10 and project memory, these are reserved for the author’s own agent work and were excluded from the sweep even though deadcode flags them:

  • internal/core/harness/* — agent modes, permissions (SystemPrompt = TODO).
  • internal/core/registry.go — AgentRegistry placeholder with intentional fake outputs.
  • All of plums/ and plums/layout — the public extension API; “unreachable” only because external user configs are the callers.

6. Affected-package dependency note

All removals were leaf functions — none changed an import edge except removing two now-unused imports inside opencode/types.go (fmt, strings). The package dependency tree from Step 1 is therefore unchanged; the only delta is that provider/opencode/types.go is now import-free (pure data + constants), which slightly tightens the “raw provider = standalone SDK” goal from DESIGN §5.4.
