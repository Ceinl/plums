Step 3 — Per-tool extensibility deep dive

Prove, per tool kind, that a user can author it as an external plugin — and where they can’t yet, pin the exact missing seam and the remediation. No risky rewrites were performed: the two open items below are DESIGN-level decisions (open questions #1–#3) reserved for the author.

1. Plan for this step

  1. For each kind, write the minimal plugin a user would author and confirm it flows end-to-end through the kernel registry into the running app.
  2. Where a built-in does not use that same path, cite the code that proves the divergence.
  3. Give an ordered remediation that closes the gap without breaking the strangler migration.

2. Fully extensible today ✓

Backend / provider

A plugin returns BackendRegistrations; the kernel registers them by name; api.backendRegistrationsFromRegistry reads them back in order. The 4 bundled backends use the identical path (one plugin each, named backend/<name>), so last-wins lets a user shadow backend/opencode or Disable backend/codex.

func (p myPlugin) Backends() []plums.BackendRegistration {
  return []plums.BackendRegistration{{
    Name: "acp", Label: "My ACP agent", Backend: myBridge{},
    Startup: func(ctx context.Context, b plums.Backend) (*plums.StartupResult, error) { … },
  }}
}

Layout

Built-in layouts (chat,split,zen,fullscreen,…) are authored with the public plums/layout builder in internal/kernel/builtin/layouts.go — the same API a user calls. Full dogfooding.

func (p myPlugin) Layouts() []plums.Layout {
  return []plums.Layout{ layout.Named("focus",
    layout.Column(layout.Chat().Height("grow"), layout.InputBox().Height(7))) }
}

Hooks & keybinds

Implement OnMessage/OnToolCall/OnSessionStart — dispatched off the loop with a thread-safe Ctx. Keybinds are declared in Settings.Keybinds and routed by HandleConfiguredKeybind.

3. Gaps — the two items blocking full dogfooding

Gap A — Components: built-ins use a privileged factory, not the public contract

What works: a user’s public component renders through ComponentFactoryForPublic → publicComponentAdapter, receives a RenderCtx + Surface, and gets input via optional KeyHandler/MouseHandler/Scrollable/SelectionProvider. chat_output proves the full path.

What doesn’t: every other built-in (editor, sessions, status_bar, input_box, info_tabs, …) is a pluginComponent whose Arrange/Render are empty stubs and which instead exposes an internal escape hatch:

// internal/app/plugin_component.go
func (c pluginComponent) Render(plums.RenderCtx, plums.Surface) {} // stub
func (c pluginComponent) AppComponentFactory() ComponentFactory { return c.factory }

// internal/api/api.go — the kernel prefers the privileged factory when present
factory := app.ComponentFactoryForPublic(component)
if provider, ok := component.(app.ComponentFactoryProvider); ok {
  factory = provider.AppComponentFactory() // reaches into *State, returns internal layout.Component
}

Consequence: a third party cannot reproduce status_bar as a public component, because the data it needs (server-lifecycle flags, agent mode) is not on RenderCtx — it’s read directly from *State inside the factory. So the public component API’s completeness is unproven beyond chat_output. This is exactly DESIGN open-question #2/#3.

Remediation (ordered, low-risk):

  1. Port one non-trivial built-in — status_bar — to a real public Component. It needs only a few read accessors on RenderCtx: ServerStarting(), ServerReady(), Mode() (it already has Session()/Streaming()). Add those accessors; that accretion is the API being driven to completeness by its own defaults (DESIGN §6).
  2. Delete that name from the DefaultPluginComponents factory list. If it renders identically, the public path is proven for a second, stateful component.
  3. Repeat for sessions/input_box; retire ComponentFactoryProvider once the list is empty. Keep chat_output’s pattern as the template.

Gap B — Commands: a legacy JSON/enum system runs parallel to Command.Do

What works: a user command with a Do func executes through runtimeCtx (Send/Chat/Shell/OpenList/SetLayout/Copy) and appears in the palette. state_palette.go merges registry commands that carry a Do.

What doesn’t: the 6 built-in slash commands carry no Do — they are name+detail only (builtin/core.go: DefaultCommands), and their behavior is resolved by a second system: commands.json → ActionSpec → PaletteAction enum → runSlashCommand. commandItems explicitly skips a registry command when a legacy entry of the same name exists and Do == nil:

// internal/app/state_palette.go
if legacy[command.Name] && command.Do == nil { continue } // built-ins fall back to the enum path

Consequence: two command systems coexist; built-ins don’t dogfood the public Do contract, so it’s unproven that Ctx’s verb set is sufficient to express them (DESIGN open-question #1).

Remediation: migrate built-ins onto Do one at a time. /new and /sessions are tractable with today’s Ctx (OpenList + a session verb). /model, /backend, /command need new Ctx verbs (open palette / list models / switch backend) — add them as the migration demands, then retire the matching ActionSpec. The legacy commands.json shrinks to empty and is deleted last.

4. Why these were not auto-fixed in this pass

Both gaps require freezing new public API surface (RenderCtx accessors, Ctx verbs) — DESIGN lists them as explicit open questions, and project memory records that component/command shape is an author-owned design decision, not an autonomous edit. The safe, completed work (audit + dead-code removal) is shipped; the gap closures are specified above ready to implement behind a decision.

Bottom line. The plugin architecture is sound and matches DESIGN: a tiny kernel, a clean public floor with verified one-way dependencies, last-wins override, Disable, doctor introspection, and a working compiled-config build. Providers, layouts, hooks, keybinds and settings are fully user-recreatable and dogfooded. Components and commands are user-recreatable for new additions; only the built-ins still ride a privileged/legacy path, and closing that is a bounded, well-specified task (Gaps A & B) gated on two small public-API decisions the author reserved.
